# Publish Dev6 Release

Publish from the `getjusto/dev6` repository only. Keep the release aligned with the repo's `electron-builder.yml`, but prefer the safer split flow below until `scripts/publish-mac.sh` is updated.

Do not start with `pnpm release:mac` or `electron-builder --publish always`. Those can leave a partial GitHub draft if DMG generation fails after ZIP upload. Build all local artifacts first, verify them, then upload/publish.

## Preconditions

- Work in `/Users/nicolaslopezj/Code/Projects/justo/dev6`.
- Keep `scripts/release-env.local.sh` local and ignored by git. Never print or commit its secret values.
- Require these env vars at runtime:
  - `APPLE_ID`
  - `APPLE_APP_SPECIFIC_PASSWORD` or `APPLE_PASSWORD`
  - `APPLE_TEAM_ID`
- Allow `GH_TOKEN` to come from `gh auth token` unless already exported.
- Use signing identity `Orionsoft SpA (3CZ24HA8DS)` unless the user explicitly changes it.

## Release Workflow

1. Confirm the repo is clean with `git status --short`.
2. Inspect the current version with `node -p "require('./package.json').version"`.
3. If the user wants a new version, update `package.json` first, commit the bump, and push `main` before publishing.
4. Preflight local build tooling before signing:
   - `node node_modules/typescript/bin/tsc -b`
   - `node node_modules/vite/bin/vite.js build`
   - Test native helpers if recent macOS quarantine/cache issues are suspected.
5. Build local artifacts without publishing:
   - Load `scripts/release-env.local.sh`.
   - Normalize `APPLE_APP_SPECIFIC_PASSWORD` from `APPLE_PASSWORD` if needed.
   - Set `CSC_NAME="${CSC_NAME:-Orionsoft SpA (3CZ24HA8DS)}"`.
   - Run `node node_modules/electron-builder/cli.js --mac --publish never`.
6. Wait through signing and notarization. Apple notarization can take minutes with no output.
7. Verify local artifacts before any GitHub publish:
   - `.dmg`
   - `-mac.zip`
   - `latest-mac.yml`
   - blockmap files
   - `latest-mac.yml` must reference the target version.
8. Inspect GitHub before upload:
   - `gh release view v<version> --repo getjusto/dev6 --json url,isDraft,tagName,assets`
   - If it does not exist, create a draft release with `gh release create v<version> --repo getjusto/dev6 --draft --target main --title "v<version>"`.
   - If it exists as a draft with partial assets, upload the complete local set with `--clobber`.
   - If it is already public, never overwrite it to sneak in changes. Ship a new version instead.
9. Upload the verified local assets:
   - `gh release upload v<version> --repo getjusto/dev6 --clobber release/dev6-<version>-arm64-mac.zip release/dev6-<version>-arm64-mac.zip.blockmap release/dev6-<version>-arm64.dmg release/dev6-<version>-arm64.dmg.blockmap release/latest-mac.yml`
10. Re-verify the draft has exactly the expected assets, then publish:
   - `gh release edit v<version> --repo getjusto/dev6 --draft=false`
11. Confirm the final public release URL, asset URLs use `/download/v<version>/`, `isDraft=false`, and the working tree is clean.

## Required Repo Knowledge

- Release config lives in `electron-builder.yml` and publishes to GitHub Releases.
- The release script is `scripts/publish-mac.sh`, but it currently publishes during build; prefer the split local-build/upload flow above.
- Local Apple secrets live in `scripts/release-env.local.sh` and must stay out of git.
- The repo is public and releases are public.
- Auto-update assets are generated by `electron-builder`; do not handcraft `latest-mac.yml`.

## Safety Rules

- Never paste or echo secret values in user-facing output.
- Never commit `scripts/release-env.local.sh`.
- Never rewrite an existing published release to sneak in code changes. Ship a new version instead.
- Never publish a draft until ZIP, DMG, both blockmaps, and `latest-mac.yml` are all present and uploaded.
- If the user asks to publish after code changes, make sure those changes are committed and pushed first so the release matches `main`.
- If a release fails mid-flight, inspect the failure before retrying. Common checkpoints are certificate naming, notarization wait time, local artifact existence, and draft release state.
- Avoid commands that print notarization process arguments, because `notarytool` can expose Apple credentials in argv. Use `pgrep -x notarytool` rather than `pgrep -fl notarytool`.

## Native Binary Cache Recovery

macOS can hang or reject cached native binaries under `node_modules` or `~/Library/Caches/electron-builder`. Symptoms include a child process stuck in `_dyld_start`, Vite native modules hanging on load, `app-builder_arm64` not starting, `7za` not starting, or `dmgbuild` failing with a Python `.so` "library load denied by system policy".

When this happens, fix the local cache before re-running signing/notarization:

- Refresh native `.node` files used by Vite/Tailwind/Rolldown by copying them through `/private/tmp` and moving them back.
- Refresh `app-builder-bin` executables before retrying packaging.
- For `7za`, if the same binary path hangs after a previous run, use a fresh-copy wrapper or restore/reinstall `7zip-bin`; test it before signing.
- For `dmgbuild` Python failures, restore the cached `python/bin/python3` symlink if it was modified, refresh Python `.so` files, and verify:
  - `<dmgbuild-cache>/python/bin/python3 -c "import subprocess; print('ok')"`
- After a workaround, restore temporary wrappers and confirm normal paths before final status.

Do not keep retrying `electron-builder` through full signing/notarization without first fixing the failing native helper; notarization is slow and repeated retries waste time.

## Common Commands

```bash
git status --short
node -p "require('./package.json').version"
node node_modules/typescript/bin/tsc -b
node node_modules/vite/bin/vite.js build
node node_modules/electron-builder/cli.js --mac --publish never
gh release view v1.0.4 --repo getjusto/dev6 --json url,isDraft,tagName,assets
gh release create v1.0.4 --repo getjusto/dev6 --draft --target main --title "v1.0.4"
gh release upload v1.0.4 --repo getjusto/dev6 --clobber release/dev6-1.0.4-arm64-mac.zip release/dev6-1.0.4-arm64-mac.zip.blockmap release/dev6-1.0.4-arm64.dmg release/dev6-1.0.4-arm64.dmg.blockmap release/latest-mac.yml
gh release edit v1.0.4 --repo getjusto/dev6 --draft=false
```

Replace `v1.0.4` with the actual version being shipped.

## Response Pattern

- State the target version and whether it was bumped in this run.
- State whether the release was notarized successfully.
- Include the GitHub release URL.
- State that ZIP, DMG, blockmaps, and `latest-mac.yml` were verified.
- Mention any residual warnings, such as missing `author` in `package.json`, only if they appeared during the release.
